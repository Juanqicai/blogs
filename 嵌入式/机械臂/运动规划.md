# 运动规划（三次多项式轨迹）

> 入门向。只讲**三次多项式**这一种：先是**两点**的最基础版本，再推广到**多点**的分段版本。
> 内容偏"怎么用 + 注意什么"，数学只推到够用。
> 上篇：[机器人运动学](./机器人运动学.md)。

## 0. 为什么需要"轨迹规划"

机器人在运动时，不能直接把两个关节角**阶跃**切换——那样末端会甩来甩去、电机冲击大、还可能撞东西。正确做法是：**在起点和终点之间，用一条平滑的曲线去"插值"关节角**，让每个时刻都有个连续、且尽量平滑的关节角目标值。

这条曲线就叫**轨迹（trajectory）**。我们这里只在**关节空间**里规划（给每个关节独立规划一条 `q(t)` 曲线），因为我们的控制是直接发关节角目标给电机的。

## 1. 为什么选三次多项式

假设已知起点 `q0`、终点 `q1`，还有两端的**速度** `v0`、`v1`。我们有 **4 个约束条件**：

```
q(0)   = q0      // 起点位置
q(T)   = q1      // 终点位置
q'(0)  = v0      // 起点速度
q'(T)  = v1      // 终点速度
```

要满足 4 个约束，最省事的做法就是用一个 **3 次多项式**（有 4 个系数），刚好够用：

```
q(t) = a0 + a1·t + a2·t² + a3·t³
```

- 2 次多项式只有 3 个系数，**装不下 4 个约束**（只能给定位置，速度没法全控）。
- 4 次/5 次能装更多，但**参数更多、更绕**。对"位置+速度"这类需求，**3 次是性价比最高、也最常用的**。

> 想要**加速度也连续**，就得用 **5 次多项式**（quintic）。但你说只写三次方，那就只讲三次。

## 2. 两点三次多项式（最基础）

### 2.1 推导系数

把 4 个约束代进去：

```
q(0)   = a0 = q0
q'(t)  = a1 + 2·a2·t + 3·a3·t²
q'(0)  = a1 = v0
q(T)   = a0 + a1·T + a2·T² + a3·T³ = q1
q'(T)  = a1 + 2·a2·T + 3·a3·T² = v1
```

解这个方程组，得到系数（`T` 是总时间）：

```
a0 = q0
a1 = v0
a2 = (3·(q1 - q0) - 2·v0·T - v1·T) / T²
a3 = (-2·(q1 - q0) + (v0 + v1)·T) / T³
```

### 2.2 最常用的特例：两端速度为零

实际里最常是"从静止出发，到静止停下"，即 `v0 = v1 = 0`。这时系数大大简化：

```
a0 = q0
a1 = 0
a2 = 3·(q1 - q0) / T²
a3 = -2·(q1 - q0) / T³
```

代入后：

```
q(t) = q0 + 3·(q1-q0)·(t/T)² - 2·(q1-q0)·(t/T)³
q'(t) = 6·(q1-q0)/T · (t/T)·(1 - t/T)
```

这个曲线有个好性质：**速度在两端为 0，中间达到最大值**，加速度也是一段线性变化，不会突变。

### 2.3 一个小例子

`q0 = 0`，`q1 = 1.0 rad`，`T = 2 s`，两端静止：

| `t` | `q(t)` (rad) | `q'(t)` (rad/s) |
|---|---:|---:|
| 0.0 | 0.00 | 0.00 |
| 0.5 | 0.16 | 0.56 |
| 1.0 | 0.50 | 0.75 |
| 1.5 | 0.84 | 0.56 |
| 2.0 | 1.00 | 0.00 |

中点速度最大 `0.75 rad/s`（= `1.5·(q1-q0)/T`）。这个就是"S 形"的速度曲线。

### 2.4 用代码实现（伪码）

```c
// 两点三次：从 q0 到 q1，时间 T，两端速度 v0,v1
void cubic_two_point(float q0, float q1, float v0, float v1, float T,
                     float t, float *q, float *v)
{
    float T2 = T*T, T3 = T2*T;
    float a0 = q0;
    float a1 = v0;
    float a2 = (3.0f*(q1-q0) - 2.0f*v0*T - v1*T) / T2;
    float a3 = (-2.0f*(q1-q0) + (v0+v1)*T) / T3;
    *q = a0 + a1*t + a2*t*t + a3*t*t*t;
    *v = a1 + 2.0f*a2*t + 3.0f*a3*t*t;
}
```

## 3. 推广：多点三次多项式（分段）

一个机械臂任务往往不是"一个点到另一个点"，而是**要依次经过好几个中间点**（waypoints），比如：`P0 → P1 → P2 → ... → Pn`。

思路很直接：**把相邻两点之间当成一段，每段用上面的三次多项式。** 这样整条轨迹由多段三次曲线拼接而成。

### 3.1 每段单独满足"两端位置 + 两端速度"

对第 `k` 段（从 `P_k` 到 `P_{k+1}`，时间 `T_k`）：

```
q_k(t) = a0k + a1k·t + a2k·t² + a3k·t³
```

- **位置约束**：起点 `q_k(0) = P_k`，终点 `q_k(T_k) = P_{k+1}`。
- **速度约束**：需要每段的**两端速度**。关键是**中间点（waypoint）的速度怎么定**，这是多点的核心问题。

### 3.2 中间点速度怎么定（三种常用策略）

| 策略 | 做法 | 特点 |
|---|---|---|
| **a. 手动指定** | 每个中间点你直接给一个期望速度 | 可控，但要自己算，烦 |
| **b. 设为零** | 每个中间点速度都设 0 | 最简单，但**每个中间点都会停顿**，走起来一顿一顿的，不好看 |
| **c. 自动估算** | 用相邻段的斜率/差分算一个"自然"的过点速度 | 最常用，走起来顺滑 |

**推荐 c**：一种常用的简单估算是用**相邻两点连线的平均斜率**，或者用**中间差分**：

```
v_k ≈ (P_{k+1} - P_{k-1}) / (T_{k-1} + T_k)     // 中间差分
```

这样中间点速度"穿过"了前后两段，轨迹在中间点处**位置连续 + 速度连续**，看起来平滑，不会停下来。

### 3.3 注意：速度连续 ≠ 加速度连续

三次多项式分段拼接，在中间点能做到**位置和速度连续**（只要两边速度取一样），但**加速度会跳变**（每段的加速度是常数，到中间点突变）。

- 如果**加速度突变**可接受（大多数抓取/点到点够用），三段就够了。
- 如果要求**加速度也连续**（例如高速、高精度、怕抖动），要用**5 次多项式**或**B 样条**。这里只到三次。

### 3.4 多点示例（伪码）

```c
// waypoints: 关节角序列 P[0..n]，每段时间 dt[i]
void cubic_multi_point(const float *P, const float *dt, int n,
                       float t, float *q, float *v)
{
    // 1. 找到 t 落在哪一段 k
    int k = 0;
    float t_acc = 0.0f;
    while (k < n-1 && t >= t_acc + dt[k]) { t_acc += dt[k]; ++k; }
    float tau = t - t_acc;                 // 段内时间
    float T = dt[k];

    // 2. 算这一段的起点/终点速度
    float v0 = velocity_at(P, dt, k);      // 起点速度(中间差分)
    float v1 = velocity_at(P, dt, k+1);    // 终点速度
    float q0 = P[k], q1 = P[k+1];

    // 3. 用两点三次公式
    float T2=T*T, T3=T2*T;
    float a2 = (3.0f*(q1-q0) - 2.0f*v0*T - v1*T) / T2;
    float a3 = (-2.0f*(q1-q0) + (v0+v1)*T) / T3;
    *q = q0 + v0*tau + a2*tau*tau + a3*tau*tau*tau;
    *v = v0 + 2.0f*a2*tau + 3.0f*a3*tau*tau;
}
```

> `velocity_at()` 用上面中间差分那套：首尾点用单边差分（`v0=(P1-P0)/dt0`），中间点用 `(P[k+1]-P[k-1])/(dt[k-1]+dt[k])`。

## 4. 使用方法和注意点

1. **每个关节独立规划**，别用统一的轨迹。每个关节的 `q0, q1`、限位、最大速度都不同，各算各的。我们电机各轴软限位是 ±135°，速度上限 `max_speed_rad_s = 2.0`，都要在规划后 `clamp` 一遍。
2. **先算速度上限，再定时间 `T`**。
   - 三次曲线的最大速度是 `1.5·|q1-q0|/T`（两端静止时）。
   - 所以给定一段行程 `Δq` 和关节最大速度 `v_max`，**最小时间** `T_min ≈ 1.5·|Δq|/v_max`。
   - 算出的 `T` 不能小于 `T_min`，否则速度超限，电机/驱动器会报错。**这是最容易踩的坑**。
3. **别超过软限位**。中间点、终点都必须在 `[min, max]` 内。我们 `±2.356 rad` 是硬性软限位，超出就要裁剪或报错。
4. **多点段间不要"顿"**。中间点速度设 0（策略 b）会一顿一顿，尽量用自动差分（策略 c）。
5. **边界条件要明确**。首末段两端速度通常是 0（静止出发、静止停下），中间段用差分速度。这决定了你每段是"两点都控速"还是"只控一端"。
6. **实时性**：如果在上位机（PC/ROS2 侧）规划好一整条轨迹，然后**按时间逐点下发**给 STM32，STM32 端只做"接收目标 + 控制"，压力小。我们项目就是这样：上位机发目标，板子只负责 500 Hz 控制环。规划本身不占板子 CPU。
7. **轨迹要喂给正确的"关节角"**。下发的 `q` 是**关节角**，而电机要的是 `q_motor = q·direction + offset`。规划用关节角，下发前记得做 `joint_to_motor()` 转换。我们 `RobStride_App_SetTargets` 里已经做了 clamp 和映射。

---

## 5. 一句话总结

- **两点三次**：4 个约束（两端位置 + 两端速度）→ 3 次多项式，两端静止时系数最简。
- **多点三次**：相邻点之间各用一段三次，中间点靠**速度连续**拼起来，别设 0 否则停顿。
- **注意**：算好 `T` 不超速、不超限位、关节角正确映射、实时轨迹放上位机逐点下发。
